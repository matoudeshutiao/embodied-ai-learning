# 2026-11-23 Day 33 笔记：让标定板始终留在画面中心

## 问题：固定手位为什么不行

腕部相机不是装在手的正下方，而是偏在一侧。以前的做法是：

```text
先定一个固定的手部 x/y/z
→ 相机跟着手走
→ 手换高度、倾斜或滚转
→ 板子在画面里跑偏，最后被切掉
```

pilot 里最直接的数据：

```text
tilt_y20: 7 markers / 8 corners
```

不是检测算法坏了，是板子已经有一大半在画面外。

## 解决方法：先定“看的方向”，再反推“手站哪里”

每一步只回答一个问题：

### 1. 相机现在朝哪看

```text
axis = R_hand · R_hand→cam · [0, 0, 1]
```

- `R_hand`：手在世界里的朝向；
- `R_hand→cam`：相机相对手的安装朝向；
- `[0,0,1]`：相机镜头的光轴方向。

算出来就是“相机镜头在世界里的指向”。

### 2. 相机应该退到哪

```text
p_cam = p_board - d · axis
```

板中心是 `p_board`，希望相机到板中心的距离是 `d`。从板中心沿着镜头反方向退 `d` 米，相机光轴就正好穿过板中心。

### 3. 手应该站到哪

```text
p_hand = p_cam - R_hand · t_hand→cam
```

相机不是长在手的原点上，有一个固定安装平移 `t_hand→cam`。把这段平移减掉，剩下的才是手的目标位置。

## 一个通俗的类比

以前像：

```text
人站死在原地，歪着手机拍桌子上的纸
→ 手机一歪，纸就跑出取景框
```

现在像：

```text
先决定“从哪个角度看纸”
再走到一个位置，让手机镜头正好对准纸的中心
```

角度可以变，站的位置跟着变，纸始终在画面中心。

## 为什么这样做有效

- 板中心始终在光轴上，不会因为高度或倾斜被推到画面边缘；
- `d` 取 0.46–0.54 m，板子半高角约 11–13°；
- 10° 倾斜后边缘约 21–23°，留在垂直半 FOV 23.4° 以内；
- 平移多样性靠额外的小 `dx/dy`，不再靠“手站死”。

## 关键边界

这里用了名义安装变换 `T_link8→camera`，但只用来**选姿态**：

```text
用来选姿态      → 可以
进入 AX=XB 求解 → 不可以
```

手眼标定的输入仍然只有：

```text
相机看到的 T_target→cam
TF 读到的 T_base→link8
```

## 结果

```text
full 15 个姿态：15/15 都是 17 markers / 24 corners
重投影 0.043–0.157 px
```

倾斜姿态的 IPPE 两组解差距：

```text
±10° 倾斜：gap 1.35–1.48 px
近正视/纯滚转：gap 0.02–0.05 px
```

板子居中以后，倾斜姿态不仅看得全，而且两解分支也区分得很清楚。
